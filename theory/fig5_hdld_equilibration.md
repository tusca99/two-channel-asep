## RESOLVED root cause: a data bug, not equilibration physics

The claim "dense never >0.5 at L=1000" came from `results/gpu/ssb_beta*.npz`,
generated by `run_all_gpu.py` with a **per-chunk reseed**:

    res = run_ensemble_cuda(..., seed=1000 + ci, ...)   # fresh trajectory each chunk

So each 2M-step chunk was a NEW trajectory restarted from random density ~0.4.
The "128-replica long run" was really 128 independent SHORT trajectories, none
long enough to reach the HD/LD basin -> dense stuck at ~0.27. NOT a physics
limit.

## Root causes (secondary, still valid)

### 1. Old MC/LD classifier was miscalibrated (FIXED)

Old: rho_avg > 0.35 -> MC. Density rises slowly toward 1/2, so this fired
prematurely at alpha~0.50 -> gave 0.477 (half the paper's ~0.8).

Fix (asep/observables.py classify_phase + fig5_boundaries.classify_point):
classify MC by **current saturation** (J plateaus at 1/4, paper Fig 4 method)
AND rho_avg > 0.45. Reclassification of existing L=1000 data gives LD->MC at
alpha ~0.70, matching the paper. VERIFIED on saved /tmp/opencode/fig5_mcld.npy.

### 2. L=2000 beta-boundary outlier was noise (FIXED via bigger ensemble)

With n_reps=8 the L=2000 asym->LD boundary jumped to 0.373 (vs 0.30 elsewhere).
With n_reps=16 it is ~0.325, consistent with L=200. Confirmed on saved
/tmp/opencode/fig5_L2000.npy. Fix: use n_reps>=16.

### 3. fig5 L=200 NaN was a fixed SSB threshold (FIXED via L-adaptive threshold)

Old: fixed asym_threshold=0.04 over-classified small L as asym (noise floor
~1/sqrt(L)); L=200 never classified LD -> NaN. Fix: threshold=0.04*sqrt(1000/L).
Verified L=200 -> asym->LD at beta~0.325 (no more NaN).

## Backend reality (why "compute" was never the blocker)

Modern backends are all within ~2x of each other:
- CPU numba: ~4.8 Mstep/s/core, ~58 Mstep/s aggregate (12 cores)
- GPU ensemble: ~70-100 Mstep/s aggregate (mass-parallel, latency-bound per thread)
- AVX/SIMD: ~13% over serial (Fenwick find/update chains are data-dependent)
- Rust: ~numba speed (326ns/step vs C 559ns/step, measured earlier)

The bottleneck is the SERIAL dependency chain inside BKL MC. No backend
parallelizes that chain. The real lever is a correct, continuous long run
(which the calibration probe achieves in ~10 min for L=1000, not the paper's
2e7/site budget).
